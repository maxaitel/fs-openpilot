Decision before measurement: a 0.20 m footprint pad cannot cover this model's empirical front-corner error wherever position error plus 1.6 times absolute yaw error exceeds 0.20 m. This is a necessary diagnostic only, not a safety bound. Score all overlapping, correlated starts on the three sealed TRAIN prefixes, separately by pilot and horizon. No tuning or exclusion based on results.

Use verified_summary and consume read_evidence fully for hash verification. Require TRAIN case and exact first-contact frames 80, 53, 82. For each start i and horizon h in 1, 5, 10, 20 control frames, require i+h < first contact. Initialize pure fsop.sim.vehicle.VehicleState at local x=y=yaw=0 with measured vx, vy, r, actual steer and actual accel. Advance with each recorded applied action at frames i through i+h-1, five step calls of dt=0.01 per 0.05 s interval. Use fixed VehicleParams() for primary, and metadata vehicle_params for privileged parameter sensitivity only. Future actions and reference world poses are scorer-only and cannot be used by a controller. Transform the recorded endpoint position into the start pose's ego frame and subtract start yaw, wrapping angular error. Report max and numpy linear p95 of Euclidean position error, absolute yaw error, absolute speed magnitude error, and position + 1.6*absolute yaw error; include count and count above 0.2 m for the latter. The 1.6 m lever uses the model's CoG-to-nose dimension, an approximation rather than exact corner radius. Observations and model both use the physical body reference as recorded; no shifting.

This is a saved-action replay, not a closed-loop or vision test. Pure bicycle integration is the model's native FSEnv setting, not PhysX's integration; LabDrive applies each action once per 20 Hz interval and advances six 1/120 s physics ticks. Preserve source hashes and results. No controller, fitting, or held-out data.
