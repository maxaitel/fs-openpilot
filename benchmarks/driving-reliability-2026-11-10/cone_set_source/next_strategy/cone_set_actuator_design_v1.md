# Direct actuator commands from a cone set

The goal is full trackdrive and RRLL skidpad within the frozen mission limits, with zero physical contacts. This design is an unimplemented candidate. It changes the representation supplied to a new raw-command head while preserving same-tick teacher controls and every existing offline, replay, physical, and final gate. It selects no checkpoint and opens no final case.

Three fits on the captured policy activation and the 296,450-parameter joint suffix failed all offline checkpoints, according to the handoff. The joint run did reach 50.3 seconds in the exposed RRLL case with nine contacts. The shared premise worth testing is that an actuator head can learn the necessary visual geometry through the original policy representation. This candidate exposes predicted cone positions directly. It cannot recover information the detector did not observe or a hidden teacher setting did not reveal.

The detector quality report finds accurate conditional matches at 5 to 10 m when predictions exist. Yet 201 of 236 driving skidpad frames lack simultaneous blue and yellow support in that range. The frozen geometric prototype returned unknown for all 706 frames because its near-field and two-sided support requirements could not bootstrap. These results do not prove that a one-sided set suffices. They justify a small controlled test before spending a main fit.

## Input and output contract

Use the original frozen checkpoint and image head. Preserve the entire original 31 million-parameter model in the package for original plan and controller diagnostics. Its captured policy activation is never an input to the new command head. The runtime still produces the original diagnostics with their existing history and queue semantics. The new head receives only the current decoded image detections, the complete supplied route desire queue, and measured body motion. Apply the existing command bounds and disclosed AS launch and brake override in their existing order. The target is `controls[tick]` at the observation tick, with the recorded teacher assertion. It is not a plan-derived action or a future label.

```python
	@dataclass(frozen=True)
	class ConeSetInput:
	    tokens: Tensor       # FP32 [B, 200, 8]
	    mask: Tensor         # bool [B, 200], true for real detections
	    desire: Tensor       # FP32 [B, 25, 8], entire supplied queue
	    motion: Tensor       # FP32 [B, 3], measured vx, vy, yaw rate

	@dataclass(frozen=True)
	class RawCommand:
	    steer_rad: Tensor    # FP32 [B]
	    accel_mps2: Tensor   # FP32 [B]

	def decode_current(image_head_output, calibration) -> ConeSetInput: ...
	def command(inputs: ConeSetInput) -> RawCommand: ...
	def reset() -> None: ...
```

The adapter also receives the route queue and measured motion when constructing `ConeSetInput`. `reset` clears the original diagnostic model's runtime history. The first candidate has no cone memory and no motion warp. This makes the treatment small and makes missing visual information visible. An empty set is legal and has a zero pooled representation and zero count. It is not evidence of free space. Do not add an emergency fallback that changes the raw-command contract or treats an empty set as a straight corridor.

Every token is `[x/45, y/45, range/45, one_hot_blue, one_hot_yellow, one_hot_orange, one_hot_big_orange, score]`. Coordinates are meters in the current ego frame, x forward and y left. Range is Euclidean. The four values are the detector's discrete predicted class, not calibrated class probabilities. Score is the decoder confidence, not a correctness probability. Do not clip positions or scores after the existing decoder's validity checks. Unknown class IDs and nonfinite inputs fail the boundary instead of becoming a cone class. Use `[vx/10, vy/2, r/1]` as in the existing head. Preserve the 200 route values without lossy pooling or a learned lap counter.

Use the pinned image-head decoder in `src/fsop/eval/img_to_bev.py` and `det_metrics.py`, including its 0.25 threshold, 100 peaks per camera, calibrated ground projection, wide and road range limits of 22 and 45 m, and 0.6 m same-class merge. Bind the actual calibration, code, checkpoint, image packing and camera order to the recipe. Two cameras can yield at most 200 entries before merging, so the 200-slot cap discards no valid decoder output. Pad and mask the rest. Record counts before and after merge and reject a contract violation. Freeze a deterministic total tie rule for score, camera, class, and pixel index before implementation. Check it against the pinned decoder on all available TRAIN probe outputs. If a tie rule changes results, record that as a new decoder and remeasure rather than claiming parity.

No cone ground truth, true pose or heading, centerline, geometry, teacher identity, future state, reference branch, or simulator progress may enter inference. External route desires and the existing AS layer are allowed and must be named in reports. Source pose and cone geometry may only enter an independent scoring diagnostic. No scorer output is an inference input.

## Exact head

For each valid token apply `Linear(8,64)`, SiLU, `Linear(64,64)`, SiLU with shared weights. Compute masked mean and masked maximum over tokens. For an empty set define both as 64 zeros. Append the valid count divided by 200. Concatenate the resulting 129 values with flattened desire `[200]` and scaled motion `[3]`. Apply `Linear(332,128)`, SiLU, `Linear(128,2)`, and multiply outputs by `[0.1, 2.0]` for steering radians and commanded acceleration in meters per second squared. There is no dropout, normalization with learned running state, learned residual, route-point loss, or temporal module.

The four affine layers have 576, 4,160, 42,624, and 258 trainable parameters, respectively. The exact total is 47,618 parameters in eight tensors. The 200 slots are not parameters. Save the exact shape inventory and verify optimizer parameter identities. Pooling makes token order irrelevant apart from floating-point reduction effects, which parity checks must bound. Do not let padded values participate in the maximum or mean.

## Fresh computation and replay

Training recomputes the encoder and image head from the actual images for every sampled anchor under `torch.no_grad()` in eval mode. Use FP32 with normal memory layout, no AMP, TF32, channels-last conversion, or feature cache. The detector outputs are detached ordinary tensors. The token and command head alone receive gradients. Batching the image forward is allowed, but no image embedding, decoded detection, or token set may be reused across optimizer draws. The 573 stored probe frames are for source checks and design diagnostics, not a training cache.

The current `decode_img` batches heatmap operations but loops over examples and converts each result to CPU NumPy before geometric projection and merge. The first implementation should run fresh batched GPU image forward under `no_grad`, transfer the needed detector outputs to CPU, call the same decoder and projection for every example, then transfer padded tokens to the training device. Measure end-to-end time and memory, including transfers, decoding, merge, and head backward. No speed or feasibility claim follows from batched encoder timing alone. Do not add a second optimized GPU decoder unless an independently frozen parity test proves identical classes, masks, counts, tie handling, and geometry at the boundary. Compare batched and singleton fresh paths on fixed TRAIN examples and the complete stored probe at the decoder boundary, including empty and dense cases. Fail on disagreement and investigate before fitting. GPU versus CPU floating-point proximity to score, peak, projection, and merge thresholds can change a discrete set. Measure and report such events; do not hide them behind an actuator tolerance.

Before the first pilot freeze CPU FP32 inference with four Torch threads for both producer and replay, as in the current integration design. Check a fixed fresh-input training-device versus CPU comparison before the fit and record discrepancies in decoded tokens and commands. Require deterministic CPU repeats and exact discrete token identity with bounded FP32 coordinates and scores under the saved contract. If discrete disagreement affects a fixed case, stop and resolve the boundary before training. CPU runtime cost is a separate measured preflight; simulated 20 Hz is not a wall-clock latency claim.

For each selected package, replay every saved producer frame and all four control phases with the same current images, tick-aligned full desire queue, motion, fresh decoder, mask, raw commands, bounds, and AS override. Compare producer and independent CPU replay at the inherited `rtol=atol=1e-5`; require exact discrete class and mask agreement. Audit all base and head hashes and the raw-to-applied command trace. Prove that the independent replay reconstructs the actual saved episode, including resets and initial history. Compare instrumented and uninstrumented outputs. ## What this test can decide

The direct cone set preserves individual positions, colors, scores, and set size rather than requiring the original compressed policy activation to retain them. It could learn a corrective direction from one visible boundary even when the rejected deterministic corridor cannot establish a two-sided path. That is a hypothesis, not a measured correction. An empty or visually ambiguous input can collapse different situations to the same route and motion, and the head may memorize recurring skidpad patterns. Exact-label conflicts, the 32-anchor screen, route-conditioned token swaps, separate transition and recovery reports, and the physical pilot can reject these failure modes.

The competing learned corridor predicts eight route points and uses a controller. Its geometry can be scored at the lookahead and inspected for branch selection, but its route-point supervision and controller introduce a separate objective and interface. The direct set head preserves the exact raw-command objective and gates, but its latent pooled set has no explicit path to inspect and inherits any unobservable teacher acceleration target. Compare both on matched frozen inputs and declared screens. A direct-head failure does not prove learned corridor failure, and a corridor geometry pass does not imply raw-command qualification.

If a separately frozen diagnostic shows that missing prior cone observations distinguish repeated current inputs and resolve a material share of the failures, propose a new temporal candidate rather than modifying this one after its results. Its past detections must be freshly computed from past images, warped into the current ego frame by integrating only measured `vx`, `vy`, and yaw rate with recorded timestamps, and include age and explicit reset semantics. Freeze association, expiration, overflow, and normalization before testing. Record odometry drift and do not import true pose. Neither the present probe's long support gaps nor the failed geometric prototype alone proves that history will solve the task.
