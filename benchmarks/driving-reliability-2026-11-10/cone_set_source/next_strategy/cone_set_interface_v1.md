# Shared cone-set implementation boundary

The isolated implementation directory is `.work/lab/cone_set_actuator_trial`. Core/training and pipeline workers own different files there. No original source file changes.

- Module `cone_core.py` exports `KIND = 'vision_cone_set_actuator_v1'`, `CONTRACT`, `ConeSetHead`, `ConeSetPolicy`, `pack_cones`, `decode_batch`, `validate_package`, `model_from_payload`, `digest_state`, and `model_digest`.
- `pack_cones(xy, classes, scores)` accepts one stock-decoder result and returns NumPy FP32 tokens `[200,8]` and Boolean mask `[200]`. Token order follows the stock decoder. It discards no entry, rejects nonfinite values/invalid classes/overflow, and zeros padding. Token fields and normalization are the independent design's `[x/45,y/45,range/45,one_hot_class[4],score]`.
- `decode_batch(image_head, calibrations)` returns one stock `(xy,classes,scores)` triple per example. It transfers raw outputs to CPU without changing values and preserves singleton decoder semantics. Compare decoding from identical raw tensors, separately from encoder device differences.
- `ConeSetHead.forward(tokens,mask,desire,proprio)` accepts FP32 `[B,200,8]`, Boolean `[B,200]`, FP32 `[B,25,8]`, and FP32 `[B,3]`. Proprio is unnormalized `[vx,vy,r]`; the head divides it by `[10,2,1]`. Tokens are already normalized. Output is physical raw `[B,2]`. Exactly 47618 parameters and eight state tensors.
- `ConeSetPolicy.load(path,device='cpu')`, `reset()`, and `__call__(obs,env)` follow the old policy shape. Public members are `model`, `head`, `device`, `controller_name`, `command_contract`, and `base_policy`. The loader fixes CPU FP32/four threads. Direct construction may support diagnostic training-device comparison.
- The policy invokes the original `ModelPolicy` once to obtain original plans and decoded image cones. It obtains the exact post-call pooled desire queue from the existing temporal object without pushing a second command. The new head reads no policy activation or hidden feature. Original controller diagnostics remain in `base_controller_diagnostic`.
- `info['controller']` has exact keys `kind`, `tokens`, `mask`, `desire`, `proprio`, `raw`, `bounded`, `applied`, and `mission_override`. Tokens, desire and proprio are the declared FP32 inputs. Mask is Boolean. All arrays become plain lists in the info record. Bounds and the AS override retain their old order. `info` retains the original decoded `cones_xy`, `cones_cls`, `cones_score`, plan and other diagnostics.
- Evidence schema is 6. Base parameter count is 31154802, head count is 47618, total is 31202420. All 417 original base states remain unchanged. The new head adds eight states.
- Packages retain `kind`, `base_payload`, `head_state`, `command_contract`, `recipe`, and `provenance`. Preserve the original full payload and controller metadata; the new fit step belongs in provenance. Original checkpoint file SHA is `48db741c8a686b2e635ae7a81b4e4c08d79fbfbd9f4dc4c163260da6f93f0cfb`. Its complete ordered model digest is `14feb933b4399f4e25131acaf60aa4abae1dad7f1421303fc66a4735fc72f652`, as bound by the original and joint audits. Validate actual base bytes against that trusted digest, not a self-asserted provenance digest alone.
- Replay recomputes fresh decoded cones and independently packs/compares all actual head inputs. It reconstructs the head from saved inputs, bounds, AS override and recorded action. Preserve every existing named physical and referee check. Do not substitute cached tokens for image inference.
